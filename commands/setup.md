---
description: First-run hits setup — install the binaries, connect through a chronicle context, select an initiative, verify with a read
argument-hint: "[chronicle context name]"
---

Walk the user through getting hits working end to end. Fix each step before moving to the next; finish by reporting what is configured and what (if anything) still needs a restart.

1. **Binaries.** Run `hits version`. If missing, or older than 0.8.1, install: `brew install impire-io/tap/hits` (installs `hits` and `hits-mcp` together), a release archive from https://github.com/impire-io/hits/releases, or `go install github.com/impire-io/hits/cmd/hits@latest` plus `.../cmd/hits-mcp@latest`. The next step needs chronicle's own CLI as well: `brew install impire-io/tap/chronicle`.
2. **Context.** The connection is a chronicle context — hits has none of its own, and there is nothing of HITS to start. `chronicle context list`. If the user named one in $ARGUMENTS, target that. If none fits: a person signs in to the hosted account with `chronicle login`; a credential on a NATS the user runs is saved with `chronicle context add`. Make it the selection with `chronicle context select <name>` — `hits` and `hits-mcp` connect with the selected context unless started with another.
3. **Author.** Nothing to set. Every write's author is the context's principal — the user's GitHub login on the hosted account, a service account's name for an agent — vouched for by chronicle. An agent that must write as itself needs its own service account and its own context, not the user's.
4. **Store and initiative.** `hits initiative list`. If it says the store or its types do not exist, the account has no HITS yet: an admin of the account runs `hits store init` once (every step idempotent); on the shared Impire install this is done. Then: filing mints item IDs from an initiative — the group of projects the user works in. If theirs is listed, `hits initiative select <slug>`; if the install has none yet, register it first (`hits initiative register <slug> <name>`). The selection is the one thing hits keeps in a config file of its own — a filing default, never a read scope.
5. **Verify.** `hits get <id>` on any known item, or `hits search` with a word. A reply means the context dials and the store answers; there is no ping. A failure is the context's — fix it with chronicle's CLI (`chronicle context show`).
6. **MCP server.** If the hits MCP tools are not present in this session, the server was not connected at startup — now that a context is selected, reconnect it (`/mcp`) or restart Claude Code. A host running several agents runs one server per agent, each on its own context.
